# 隐私与公开仓库规则（Privacy）

> InkDock / 墨台 · P0 文档
> 本仓库**允许公开**，但公开内容必须**完全脱敏**。真实诊断只存在于 `private/`，且 `private/` 永不入库。

---

## 1. 铁律

1. **公开文档 = 抽象能力结论**；**私有报告 = 本机真实现场**。两者永不混写。
2. `private/` 必须被 `.gitignore` 排除；提交前务必 `git status` 复核。
3. 不得把“记忆”当“现场”：任何能力结论都要有本机只读证据；没验证的标注“未验证”。

---

## 2. 禁止进入公开区的内容

- 真实**服务名 / 容器名 / 项目名**。
- 真实**路径**（尤其是个人目录、安装绝对路径、挂载点）。
- 真实**地址与端口**（含内网、NAT、回环、转发端口）。
- **环境变量**及其值。
- **账号 / token / secret / cookie / 订阅 / 节点 / 连接目的地址**。
- **配置全文**（可引用字段名，不可贴内容）。
- **日志正文 / 进程命令行 / 文件内容**（可能含密钥）。
- 设备标识（序列号、IMEI、UUID、主机名、MAC、SSID）。
- 密钥库、签名文件、备份文件。

---

## 3. 允许进入公开区的内容

- 公开软件名与版本号（如 Droidspaces、Docker、Compose、systemd、mihomo）。
- 源码必须使用的公开产品标准安装路径及通用默认目标名（例如 arch）可出现；这些不是业务服务身份或凭据。本机实际业务名称、私人目录和访问地址仍禁止上传。
- 公开产品的命令行**开关/字段名**（如 `--format`、`show/info/check`），因为它们是开源公开接口。
- 抽象的**能力结论**（“支持 JSON 输出”“controller 绑定回环且无鉴权”）。
- 设计性内容（架构、威胁模型、路线图、需求）。

---

## 4. 脱敏手法

| 原始 | 公开写法 |
| --- | --- |
| 具体容器/服务名 | “本机唯一的 Droidspace 容器 / 某服务” |
| 绝对安装路径 | “<Droidspaces 安装目录>” |
| 内网/NAT/回环地址 | “回环地址 / NAT 地址” |
| 具体端口 | “转发端口（若干）” |
| 配置项 | 只写键名，如 `port_forwards`，不写值 |

---

## 5. 提交前自检清单

- [ ] `private/` 在 `.gitignore` 中，且 `git status` 不显示其内容。
- [ ] 公开文档中搜索不到 IP / 端口 / 绝对路径 / 服务名 / 容器名。
- [ ] 搜索不到 `secret`、`token`、`cookie`、`password`、`sub`（订阅）等词的非占位用法。
- [ ] 无日志正文、无环境变量、无命令行、无配置全文。
- [ ] 没验证的结论标注“未验证”。
- [ ] 本机与运行时标识均被抽象。

---

## 6. 一旦泄漏

1. 立即从版本历史移除（若已 push，需重写历史并强推，且视为泄露处置）。
2. 轮换受影响凭据（token/cookie/secret）。
3. 记录事件与处置到 `private/`，不写入公开区。
