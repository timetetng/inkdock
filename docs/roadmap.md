# 路线图（Roadmap）

> InkDock / 墨台 · P0 文档
> 主线：**P0 只读兼容性 → P1 Docker 真实闭环 → P2 systemd/Compose/文件 → P3 网络/代理 → P4 打磨**。
> 终端为可选后置项。原则：**先只读、后写入；写入必预览、确认、备份、回滚。**

---

## P0 · 只读兼容性（当前阶段）

**目标**：把“这台机器上到底有什么能力”用只读方式钉死，形成可审查的公开结论 + 私有证据。

**范围**
- 只读核对 Droidspaces 版本、CLI、JSON 能力、进入方式、配置字段、端口机制。
- 只读核对 Docker 引擎/API/socket、Compose、有限列表与 labels。
- 只读核对 systemd/journal 能力、有限监听元数据、文件元数据。
- 只读核对代理 controller 鉴权/可达性与守卫行为。
- 输出 8 份文档；公开文档完全脱敏；`private/` gitignore。

**禁止**：mount/umount、启停任何服务/容器、改转发/iptables、改配置、拉镜像、exec 进 Docker 容器、`up/down`、网段扫描/ping、修改代理、在 PID1 mount ns 挂载。

**验收**：文档齐备；已验证/待验证界线清晰；无敏感数据进入公开区；`private/` 被忽略。

---

## P1 · Docker 真实闭环

**目标**：把“服务”域在只读 + 低风险写入上跑通。

**内容**
- 概览：Droidspaces/Docker/Compose 版本、容器汇总、资源采样。
- 服务列表：Compose 项目聚合 + 裸容器；状态、端口、labels。
- 详情：状态、端口、日志（限长/脱敏/可取消）。
- 低风险写入：单个容器 `start/stop/restart`（L2：确认、超时、取消、结构化错误）。
- root bridge 落地：类型化请求、白名单、argv、超时/取消。

**验收**
- 只读字段来源可追溯；不误报。
- 启停有确认与错误回执；失败不留下半状态。
- 端口视图能同时显示 Docker→运行时 的发布关系。

---

## P2 · systemd / Compose / 文件

**目标**：补齐收藏 unit、Compose 来源、文件读写。

**内容**
- 收藏 systemd unit：状态/日志（D-Bus 优先）。
- Compose：项目聚合、配置来源、按项目启停（L2+，需确认）。
- 文件：浏览、元数据、只读打开；L2 文件操作（删除/移动/覆盖）带确认与回收/备份。

**验收**
- unit 状态与日志可靠；Compose 来源准确。
- 文件只读打开走 FileProvider；写操作可回滚。

---

## P3 · 网络 / 代理

**目标**：两级端口可视化 + 代理协同。

**内容**
- 端口两级模型可视化：配置意图 / 内核规则 / 实际监听，冲突检测。
- 端口与挂载写入（L3）：预览 diff、确认、备份、回滚、**热生效状态标注**。
- 代理页：mode、controller 可达性与鉴权状态（只表示有无 secret）、守卫是否可能覆盖。
- 守卫协同：显示判据、提供显式暂停/覆盖（高风险、需确认、可回滚）。

**验收**
- 任何网络写入都有回滚路径；未验证的热生效一律显式标注。
- 代理切换的覆盖风险有明确提示与应对。

---

## P4 · 打磨（终端可选）

**内容**
- 主题/动画/无障碍打磨；深浅色一致性。
- 性能：采样、缓存、流式日志的最终配额。
- 终端：可选、后置，设置中开启。

**验收**
- 长时间运行稳定；资源占用可接受；终端不影响主线。

---

## 服务扩展主线

遵循 [extensions.md](extensions.md)。P1 将 UI、能力接口、适配器分开并增加契约模型；之后验证声明式样例、本地导入/禁用/卸载及权限边界。Pi 先接只读会话与任务，模型/凭据写入单独验收。不是插件市场，不承诺任意服务零代码接入。

## 贯穿性约束（每个阶段都适用）

- 只 GitHub Actions 构建；设备/容器不装 Android SDK/Gradle/NDK。
- 不开放 Docker TCP、无认证 root HTTP。
- 用户输入不拼 shell；一律 argv。
- 不承诺未验证的热生效。
- 真实诊断只进 `private/`；公开文档完全脱敏。
