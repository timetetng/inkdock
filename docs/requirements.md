# 需求规格（Requirements）

> InkDock / 墨台 · P0 文档
> 本文区分 **已确认**、**待决策** 与 **可验收标准**。任何未在本机验证过的“能热生效”结论都不写进需求，
> 一律标为待验证。

---

## 1. 已确认需求

### 1.1 产品边界

- 完全 personalized 的 Android 运维 APK，**只管理这台已 root 手机**上的 Droidspaces 与服务。
- 明确**不做**：通用软件、远程主机、账号系统、多机发现、插件市场和任意代码热加载。
- 必须支持受控服务扩展，Pi 为后续验收案例；契约与分期见 [extensions.md](extensions.md)。
- 技术栈：原生 Kotlin / Jetpack Compose / Material 3；墨绿主色、现代圆角、轻量动画、深/浅色。
- 命名：App 名 **InkDock / 墨台**，仓库名 `inkdock`。
- 允许公开，但**绝不上传隐私**。
- 只 GitHub Actions 构建；设备 / 容器**绝不安装** Android SDK、Gradle、NDK；P0 不写实现、不构建 APK。

### 1.2 信息域（四个 + 可选终端）

| 信息域 | 内容 | 优先级 |
| --- | --- | --- |
| 概览 | 设备/运行时概览、容器与关键服务健康、资源采样 | P0/P1 |
| 服务 | Docker 容器、Compose 项目、收藏的 systemd unit；状态、日志、端口 | P1/P2 |
| 网络 | 端口两级发布/转发视图、代理(已有内核)状态与切换 | P3 |
| 文件 | 浏览 + 基本操作；外部应用**只读打开优先**；编辑回写后续 | P2 |
| 终端 | 可选、后置，不占首期主导航 | P4/可选 |

### 1.3 服务域已确认行为

- 覆盖 **Docker / Compose / 收藏的 systemd unit**。
- 展示：状态、日志、端口。
- 长按复制 `ip:port`。
- 仅当**明确是 Web 服务**时，点击才打开浏览器；URL 路径可自定义。
- Compose 项目需能显示其**配置文件来源**，并区分 compose 管理与“裸”容器。

### 1.4 文件域已确认行为

- 浏览与基本操作。
- 外部应用**只读打开优先**；编辑回写属于后续阶段。

### 1.5 mihomo（已有内核）已确认行为

- 只管理**已有内核**，不实现 Android VPN。
- 必须顾及**已有代理守卫 / 脚本**，避免 GUI 切换后马上被覆盖。
- P0 诊断只读必要键，不输出 secret、订阅、节点、目的地址、token；未来代理页面应可查看与切换节点，但凭据始终脱敏。

### 1.6 root bridge 已确认约束

- 本地 root bridge；**按需连接**。
- 不开放 Docker TCP，不开放无认证的 root HTTP 服务。
- 所有动态参数**安全传递**（argv，不拼 shell）。
- 必须支持超时、取消、结构化错误。

### 1.7 端口模型已确认

- 端口区分三层：**Docker 容器 → Droidspaces 容器 → Android 宿主**。
- 是**两级发布/转发**（Docker publish → Droidspaces port-forward）。
- P0 只读；后续写入需要：App 内确认、预览、冲突检测、备份与回滚。
- **不承诺**未经本机验证的热生效。

## 2. 待决策（Open Questions）

> 这些点必须在实现前用本机只读/受控实验确认，不能靠记忆。

| 编号 | 问题 | 影响 | 建议验证方式 |
| --- | --- | --- | --- |
| Q1 | 宿主侧 Droidspaces `check` 的能力布尔（loop/user_ns/cpu_limit/pids_limit 等）与容器内是否一致？ | 兼容性门禁 | 在宿主 root 通道跑 `droidspaces --format check` 与容器内结果对比 |
| Q2 | `start/stop/restart/enter/run/pid` 是否始终只有文本输出？哪些字段稳定可解析？ | 服务控制可靠性 | 观察多版本输出；优先用 `--format show/info/check` JSON |
| Q3 | `--format show` 的 `total` 与 `running` 计数语义？`uptime_sec=0` 是否为已知缺陷？ | 概览数据正确性 | 多次采样、跨容器对比，必要时用 `/proc` 兜底 |
| Q4 | Android 宿主侧转发端口是否真的处于监听（而非仅规则存在）？ | 网络页可信度 | 宿主侧 `ss`/连接测试（受控、非扫描） |
| Q5 | 修改 Droidspaces `port_forwards` / `bind_mounts` 的生效方式与回滚点？ | 写入功能 | 逐条记录“配置 → 规则 → 实际监听”的因果 |
| Q6 | mihomo GUI 切换是否在守卫周期内被覆盖？覆盖窗口多长？ | 代理页设计 | 读守卫脚本 + 计时器；**真实验证需要一次写入**，P3 再做 |
| Q7 | 收藏的 systemd unit 用 D-Bus 还是 `systemctl` 文本？ | 服务页实现 | 对比 `systemctl show -p ...` 与 D-Bus 可用性 |
| Q8 | 文件访问范围：Android 存储 vs 容器内文件系统？ | 文件页范围 | 明确各自可达路径与权限 |
| Q9 | 日志流式读取的边界（tail 行数、时间窗、背压、脱敏）？ | 体验与安全 | 采样测试 + 明确“默认不显示可能含密钥的正文” |

## 3. 页面与交互

### 3.1 全局

- Material 3，墨绿主题，深/浅色；底部主导航 5 项以内（概览/服务/网络/文件，终端后置）。
- 顶部为“当前运行时”上下文（本机唯一 Droidspaces 环境 + 其内 Docker 引擎），不做多环境切换。
- 全局行为：下拉刷新、按需刷新（进入页面时）、可取消的长任务、统一错误卡片（结构化错误码 + 可复制详情）。

### 3.2 概览

- 运行时健康：Droidspaces 版本、Docker 引擎版本、Compose 版本、容器数量与状态汇总。
- 资源采样：CPU / 内存 / 存储占用（采样，不持续高频）。
- 快捷入口：进入服务 / 网络 / 文件。
- 只显示**结论 + 来源**，不显示原始敏感数据。

### 3.3 服务

- 列表分组：Compose 项目（按 project 聚合）→ 裸 Docker 容器 → 收藏的 systemd unit。
- 行内展示：名称、状态、镜像、端口徽标；长按复制 `ip:port`。
- 详情页：状态、日志（可选时间窗）、端口、labels、compose 配置来源。
- “打开浏览器”仅对明确 Web 服务出现，可自定义 URL 路径。

### 3.4 网络

- 两级端口视图：
  - Docker 发布：`容器端口 → 宿主机(Droidspace)端口`。
  - Droidspaces 转发：`Droidspace 端口 → Android 端口`。
- 代理（已有内核）：当前 mode、controller 可达性与鉴权状态（只表示“有无 secret”，不显示内容）、守卫是否可能覆盖。
- 明确标注哪些是**配置意图**、哪些是**实际监听**（区分展示）。

### 3.5 文件

- 目录浏览、排序、大小/时间元数据。
- 打开：优先 `ACTION_VIEW` 只读分享；后续阶段才做编辑回写。
- 危险操作（删除/移动/覆盖）属于 L2+，需确认与回收站/备份策略。

### 3.6 终端（可选）

- 后置；提供进入运行时的交互式 shell。
- 默认不在一期出现；可在设置中开启。

## 4. 危险操作分级

| 级别 | 定义 | 示例 | UI 要求 |
| --- | --- | --- | --- |
| **L0 只读** | 不改变任何状态 | 列容器、看日志、看端口、看文件元数据 | 直接执行 |
| **L1 低风险写** | 可逆、影响小 | 收藏/取消收藏 unit、切换当前分流 mode（若守卫允许） | 轻确认 + 结果提示 |
| **L2 中风险写** | 影响服务可用性 | start/stop/restart 服务、删除文件、写文件 | 显式确认 + 预览 + 可回滚 |
| **L3 高风险写** | 影响网络/存储可达性 | 改 `port_forwards`、`bind_mounts`、iptables/NAT、挂载 | 确认 + 预览 diff + 冲突检测 + 备份 + 回滚 + **明示“是否热生效未验证”** |

**硬规则**

- 任何 L2/L3 均不得拼接用户输入进 shell；一律 argv。
- L3 禁止在 PID1 的 mount namespace 内 `mount/umount`（历史事故：mount 事件传播导致系统卡死/黑屏）。
- L3 的“热生效”承诺必须来自本机实测；否则一律显示“需要重启/未验证”。

## 5. 各阶段可验收标准

### P0 · 只读兼容性（本文档阶段）

- [x] 交付 8 份文档（README、requirements、architecture、roadmap、privacy、.gitignore、private/compatibility、docs/compatibility）。
- [x] 明确“已验证 / 待验证”界线，且公开文档完全脱敏。
- [x] `private/` 被 `.gitignore` 排除。
- [x] 主助手已初审并修正部分安全表述；P1 已开始，构建和真机能力仍待验证。

### P1 · Docker 真实闭环

- 能列出 Docker 容器、区分 Compose/裸容器、读取状态与端口。
- 能对单个容器执行 start/stop/restart，并有超时/取消/结构化错误。
- 端口视图能同时展示“两级”来源。
- 只读阶段不误报：所有状态字段来源可追溯。

### P2 · systemd / Compose / 文件

- 收藏 unit 的状态/日志可读。
- Compose 项目可聚合展示并标注配置来源。
- 文件浏览 + 只读打开可用；L2 文件写操作具备确认与回滚。

### P3 · 网络 / 代理

- 端口两级模型可视化，冲突检测可用。
- 代理页可读 mode/可达性/鉴权状态；切换行为与守卫的交互有明确说明与保护。
- 任何网络写入均有预览、备份、回滚、热生效标注。

### P4 · 打磨（+ 终端可选）

- 主题/动画/无障碍打磨；性能与缓存策略定型。
- 终端作为可选后置功能。

## 6. 非功能需求

- **超时**：所有 root bridge 调用带可配置短超时；默认值保守。
- **取消**：长任务可取消，取消后不得留下半状态。
- **结构化错误**：统一错误码（超时/权限/未找到/解析失败/后端拒绝）。
- **输出限长**：日志与命令输出必须有上限，避免内存与隐私风险。
- **可测性**：验证脚本与证据进入 `private/`，公开文档只保留脱敏结论。
